# Архитектура аудиоконвейера (обобщённая)

> Схема живого конвейера, на котором работает этот репозиторий. Пути, имена бакетов и функций обобщены.

## Принцип

**Один inbox, один конвейер, один журнал.** Сколько бы ни было точек входа
(iPhone, Meetily, будущие), дальше L0 логика единая. Новые источники
подключаются к inbox, а не порождают новый конвейер.

## Точки входа

| Источник | Транспорт | Статус |
|---|---|---|
| iPhone «Диктофон» | Шорткат → Cloud Function `<inbox-function>` → S3 `inbox/` | ✅ работает |
| Meetily (десктоп) | Локальные файлы → тот же обработчик | ✅ работает, слить в общий inbox |
| Будущие (диктофон Windows, часы) | Любой способ положить файл в inbox | — |

## Слои

- **L0 — сырое аудио**: S3 `<your-bucket>/inbox/`. Запись доступна
  для прослушивания в любой момент. После обработки — `inbox-processed/`.
- **L1 — транскрипт**: `06-Встречи/YYYY-MM-DD — <имя>.md`. SpeechKit v3,
  разметка спикеров, таймкоды.
- **L2 — саммари**: LLM-разбор в ту же заметку (тезисы, решения).
- **L3 — действия**: извлечённые задачи/обещания/ожидания + черновики
  (письма, сводки). Пометка `#к-разбору`.

## Журнал

Двухуровневый:

1. **Машинный** `scripts/pipeline-journal.jsonl` — событие на каждый шаг:
   `{ts, id, source, layer, action, status, size, duration, error}`.
2. **Человеческий** — frontmatter заметки:

```yaml
---
id: 2026-11-21-113731-nizhegorodets-14
источник: iPhone (вебхук)
статус: summarized   # new → transcribed → summarized → reviewed
длительность: 22:14
спикеры: [Спикер 1, Спикер 2]
люди: [Слава]
темы: [Макс-бот, база-данных]
аудио: s3://<your-bucket>/inbox-processed/...
---
```

Связи между заметками строятся из `люди:`/`темы:` через Dataview и граф —
без ручного тегирования.

## Надёжность («без администрирования»)

- Идемпотентность: повторный запуск не дублирует заметки (дедупликация по
  имени + размеру).
- Перенос в `inbox-processed/` только после успешной записи заметки.
- Ошибка одной записи не останавливает остальные; ошибка пишется в журнал.
- Два режима запуска: событийный (локальная автоматизация каждые 15 мин
  днём) + страховочный вечерний прогон 21:37.

## Ограничение

Облако не пишет в локальный Obsidian → «автосаммари после остановки записи»
= локальный цикл с периодом ~15 минут, не мгновение.

## Дорожная карта

1. ☐ Слить ветку Meetily в общий inbox (единая функция обработки).
2. ☐ Добавить `pipeline-journal.jsonl` во все шаги.
3. ☐ Frontmatter со статусами/людьми/темами в шаблон заметки.
4. ☐ Событийный запуск (15 мин) в дополнение к 21:37.
5. ☐ Уровень L3: извлечение задач и черновики писем.
6. ☐ Публикация iPhone-связки на GitHub (перед пушем — перевыпуск токена!).
